# 第一次使用：把协调工作整理成可信的成果

[English](first-session.en.md) | [简体中文](first-session.zh-CN.md) · [返回首页](../README.zh-CN.md)

**虚构演示。**以下是编写的示例对话，不是实测记录或用户评价。数字由案例中的虚构用户提供，不代表 Skill 的效果数据。

**用户：** 用职场大神养成计划。我两个月后要述职，但平时都是催人、开会，不知道有什么成果。

**助手：** 先聊最近一件事。当时具体卡在哪里？你做了什么让事情继续往前走？

**用户：** 一次活动上线前，三个团队拿的需求版本不一样。我整理了六个有争议的问题，做了确认表，找负责人确认成同一个版本。最后按原定日期上线了。

**助手：** 其中哪部分是你负责的？有什么材料可以支持这个结果？

**用户：** 确认表和后续跟进是我负责的，整个活动不是我主导的。有确认表和上线通知，但不知道有没有减少返工。

**助手：** 可以先整理成这样一张成果卡：

| 项目 | 草稿 |
| --- | --- |
| 个人贡献 | 梳理三个团队之间的六项需求分歧，协调负责人确认统一版本。 |
| 已知结果 | 活动按原定日期上线。这是团队结果，当前记录不足以证明由你的协调工作单独促成。 |
| 依据 | 你表示有确认表和上线通知；本次尚未查看这些材料。 |
| 可复用经验 | 统一的问题确认记录可能帮助暴露理解差异，可以在下一次交接时更早试用。 |
| 尚不清楚 | 是否减少返工、减少多少；暂不写成已证实的提升。 |

用于述职时，可以这样写：

> 在活动上线过程中，梳理三个团队之间的六项需求分歧，通过问题确认表和负责人跟进推动执行版本统一。活动按原定日期上线；个人贡献集中在需求确认与协作推进，不包括整体项目主导。

一个可选的下一步：下次交接前复用确认表，观察能否在进入执行前发现分歧。这是待验证的尝试，还不是已经证明的改进。

这份草稿目前只在对话中，尚未保存到文件。

**用户：** 能不能再给我一个有趣的称号？

**助手：** **跨部门混乱终结者。**适合放在趣味卡片上，不作为真实职位或正式述职用语。

## 想继续时可以这样说

- “保存到我指定的私人档案目录。”
- “我再说一件上个月的事。”
- “根据这些记录帮我整理转正述职材料。”
- “我们用中文讨论，但最终输出英文绩效自评。”

下次会话需要读取原档案或你提供的对话记录。Skill 本身不会自动获得跨会话永久记忆。
