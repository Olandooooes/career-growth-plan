# 从琐碎工作到 KPI 自评：运营专员完整案例

[中文首页](../README.zh-CN.md) | [English home](../README.md)

**你只需要提供考核指标和原始工作记录，就能得到：贡献对应表 → 可提交的自评 → 证据补充清单。** 无需先做角色测试，也不用先把流水账改写成漂亮的成果。

本案例来自一轮对话中的模拟试用。岗位、指标、记录和数字全部虚构，用来演示输出方式；不是实际用户成绩或跨模型测试报告。

## 一眼看懂前后变化

| 原来只会这样说 | 整理后可以说清的贡献 |
| --- | --- |
| 每周催人交数据、做周报 | 协调数据收集与核对，完成4期报告，并如实呈现一次延期 |
| 图片改了三次，还要检查优惠券 | 整理素材修改要求；发现优惠券异常，跟进修复并复测 |
| 天天回答同事问题 | 将反复出现的问题整理为包含8个问题的FAQ，供团队查阅 |
| 一直催退款，周报写了好几次 | 按不同工单去重；区分个人材料整理与团队追回款项 |

## 1. 用户输入：可以整段复制试用

在已经加载本 Skill 的工具中，复制下面的提示词即可。也可以让助手读取本地项目的 `SKILL.md` 和 `references/kpi-accomplishments.md` 再试用；这不等于安装或保存个人档案。

```text
用 $career-growth-plan 帮我整理本月 KPI 考核自评。
我的岗位是运营专员，做了很多琐碎工作，但不擅长表达贡献。
请跳过角色测试，按贡献归类，对应我的实际考核指标，
写成可直接放进考核表的自评，并把需要补的证据单列出来。
不要编造结果或把团队成果写成个人成果。

以下全部是模拟记录：

考核周期：一个月。
公司KPI：
1. 周报交付：4期，全部按时提交。
2. 活动执行支持：完成2场活动的上线检查。
3. 异常事项跟进：月内关闭至少10个异常工单。
4. 知识沉淀：完成1份常见问题说明。

原始工作记录：
- 第一周：催销售、客服交数据，合并周报，周五交了。
  发现退款数对不上，找客服改了。
- 第二周：又催数据、做周报，周五交了。
  活动A的图片改了三次，我把修改点整理给设计；
  上线前检查了链接和优惠券，发现券不能用，
  研发修好后我复测通过。
- 第三周：周报周一才交，晚了。
  源数据周五下午还没齐，我也没提前提醒风险。
  活动B检查完交给负责人，按计划上线。
- 第四周：周报周五交了，修正了两条重复订单。
- 以上周报的约定截止时间为每周五；第一、二、四期按时。
- 每天回答同事关于优惠券、退款流程的问题，没统计次数。
  整理了一份包含8个问题的FAQ，发到群里，不知道有没有人看。
- 月初和月中周报里都写了“继续催退款工单R07”，
  其实是同一个工单。
- 月底查工单台账：我跟进的12个不同工单，9个已关闭，
  3个还在处理。
- 其中一个退款问题由财务和客服处理，团队追回8000元。
  我负责整理订单材料、跟进进度，没有参与金额核算。
```

## 2. 输出：先把工作和 KPI 对上

下面是本次模拟整理后的示例。依据均为模拟输入，尚未检查原始附件；实际输出的措辞可以变化，但事实、归属和达标判断应保持一致。

| 贡献归类 / 对应KPI | 个人贡献与实际结果 | 达成情况 | 依据与待补证据 |
| --- | --- | --- | --- |
| 报告交付与数据核对 / 周报交付 | 完成4期周报，3期按时；协调修正退款数据，剔除2条重复订单 | 部分达成：数量达标，全部按时的目标未达成 | 输入明确了交付情况；待补提交时间、截止时间及修正记录 |
| 活动上线检查 / 活动执行支持 | 完成2场活动检查；发现活动A优惠券异常，跟进修复并复测通过 | 按记录达成 | 待补两场活动检查清单及修复、验收记录 |
| 异常跟进与协作 / 异常事项跟进 | 跟进12个不同工单，关闭9个；整理退款材料并跟进团队处理 | 未达成：关闭数量比目标少1个 | 输入引用工单台账；待补台账及关闭状态，核实去重 |
| 知识沉淀 / 知识沉淀 | 整理并分享1份包含8个问题的FAQ | 文档交付达成，使用效果尚不明确 | 待补FAQ及分享记录；采用率与节省时间未知 |

修正数据是周报交付的补充贡献，不凭空新增公司KPI；8000元是团队结果，不作为个人追回金额或另一次工单关闭成果。

## 3. 输出：可以放进考核表的自评

以下文字可以在本模拟场景下直接复制。用于真实考核时，请替换成自己的记录，并核对事实和公司表格要求。

### 周报交付与数据质量

本月协调销售、客服的数据收集与核对，完成4期运营周报，其中3期按时提交。核对过程中发现退款统计不一致问题并协调修正，剔除2条重复订单。按时交付目标未完全达成；第三期源数据未及时齐备，我对交付风险的提醒也不够提前。下月拟明确数据提交截止时间，对未齐备项提前提示风险并同步预计交付时间。

### 活动执行支持

完成活动A、B两场活动的上线检查。活动A筹备过程中，整理素材修改要求并跟进设计调整；上线检查时发现优惠券不可用问题，协调研发修复并完成复测。活动B完成检查后交付负责人，并按计划上线。

### 异常事项跟进

本月跟进12个不同异常工单，已关闭9个，另有3个持续处理中，距离月内关闭10个的目标仍有1个差距。其中一项退款问题由财务、客服协作处理，团队追回8000元；我承担订单材料整理与进度跟进工作。下月拟逐项确认未关闭工单的阻塞原因、责任人和预计完成时间。

### 知识沉淀

根据日常业务咨询，整理优惠券使用与退款流程中8个常见问题及处理方法，形成1份FAQ并分享至团队群，供同事查阅。后续拟收集使用反馈，补充仍需反复解释的问题。

## 4. 输出：证据单独补，不混进提交文字

| 优先补什么 | 能支持什么判断 |
| --- | --- |
| 周报提交时间与约定截止时间 | 核实4期交付、3期按时及一次延期 |
| 活动检查清单、问题修复与复测记录 | 核实两场活动检查和优惠券异常处理 |
| 去重后的工单台账与关闭状态 | 核实12个不同工单、9个关闭、3个处理中 |
| FAQ文档及群内分享记录 | 核实文档内容和交付；使用效果需另收集反馈 |

涉及8000元的团队结果，提交前还应核对退款记录与职责分工。若无法确认金额，可保留个人材料整理与跟进的贡献，删去金额表述。

## 5. 为什么这份自评比流水账更容易读懂？

- **说清具体贡献：**“催人”展开为协调数据收集，“改图”展开为整理修改要求，“答疑”形成可查阅的知识材料。
- **保留真实责任：**研发修复的问题写成协调与复测，财务、客服追回的款项保留为团队成果。
- **同一成果只算一次：**R07在两次周报里出现，仍然只是一张工单；图片改三次也不等于完成三场活动。
- **没有效果数据也能表达：**FAQ有明确交付物，但没有被写成“效率提升30%”或“显著减少咨询”。
- **未达标也能写得专业：**如实说明差距、已做工作和下一步，不把延期与数量不足改写成达标。

## 换成你自己的工作，怎么用？

1. 把岗位、考核周期和公司的指标写出来；没有指标也可以先整理贡献主题。
2. 贴上原始记录，保留重复跟进、未完成事项和团队分工，不必先润色。
3. 让 Skill 输出对应表、自评和证据清单，核对后再使用。

```text
用 $career-growth-plan 帮我整理KPI自评。
岗位：……
周期：……
考核指标及目标：……（没有就注明没有）
工作记录：……
请先给我可用的草稿，按实际贡献归类，单列证据缺口。
```
