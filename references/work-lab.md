# Work lab: expression and rehearsal

Read when the user wants to translate everyday work into a better description, or practice a workplace conversation. Follow the main skill's language and factuality rules. Give useful output from the story already supplied; no discovery quiz is required.

## Work translator

Offer three short versions when the user asks for a playful transformation:

1. **Everyday / 人话版:** Name what they actually did in plain language.
2. **Legend / 江湖版:** An affectionate, exaggerated metaphor about the task. Label it playful; keep it out of formal documents.
3. **Professional / 专业版:** A clear statement of actual responsibility, action, and known result. Improve specificity, not seniority. If no result was supplied, describe the action without manufacturing impact.

For a formal-only request, provide just the professional version. For a playful-only request, do not insist on all three. Ask one follow-up only if it would materially improve the statement.

Example input: “运营。今天追设计改图，找研发确认活动页，需求变了三次。”

- 人话版：跟进活动素材修改，并与研发确认活动页需求。
- 江湖版（趣味称号）：活动上线前的跨部门混乱驯服师。
- 专业版：跟进活动素材迭代与活动页需求确认，协调设计、研发之间的变更沟通。

Do not infer that the page launched, the user led the project, or communication became more efficient. Avoid replacing understandable work with jargon. A good translation lets the user say “that's what I did, and now I can explain it.”

## Conversation rehearsal

Use for asking for ownership, negotiating priorities, discussing contributions, or preparing a difficult work conversation. It is a practice simulation, not a prediction of another person's behavior.

If context is missing, ask for the counterpart and the desired outcome, ideally in one short question. Reuse supplied context. Offer a plausible opening line the user can actually say, or let them go first if they request roleplay.

Play the counterpart for one turn at a time, then wait. Keep pushback realistic and proportionate; do not make the counterpart instantly agree or caricature them as hostile. The user can say “pause / 暂停” to get coaching, “gentler / 温和一点” or “harder / 难一点” to change the practice. Do not dump both sides of a long conversation when the user wants to practice.

After the user ends practice or reaches a natural stopping point, give a short debrief: what their wording achieved, one change worth trying, and a fallback if the request is declined. Distinguish influence from authority. Do not recommend threats, manufactured offers, or assumptions about legal rights. Never send the rehearsal to anyone.

Example scenario: a manager assigns another urgent task while the user wants project ownership. Help them clarify which existing task should move and suggest a bounded responsibility. A useful fallback can be agreeing on a review point or written priorities; “just work harder” is not the default.
